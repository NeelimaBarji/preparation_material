# Weekly Study Schedule — 12 Hours

Use this as a repeatable cadence across the six-month daily plan.

| Day | Focus | Time | Expected output |
|---|---|---:|---|
| Monday | Concepts and notes | 1.5 h | One-page summary and diagrams |
| Tuesday | Python or Java coding | 1.5 h | Working exercise with tests |
| Wednesday | AI concepts + interview Q&A | 1.5 h | Two spoken answers and flashcards |
| Thursday | Implementation | 1.5 h | Incremental project feature |
| Friday | Interview practice/revision | 1 h | Timed answer or coding drill |
| Saturday | Deep project work | 3 h | Demonstrable feature |
| Sunday | Assessment, documentation and planning | 2 h | Weekly score, README update, next-week plan |
| **Total** | | **12 h** | |

## How to use each session
- Start with a specific outcome, not “watch a course.”
- Spend at least half the time writing or reviewing code.
- Record commands, configuration and common errors.
- End with a brief explanation as though teaching a teammate.
- Commit work in small logical changes.

## Busy-week fallback
If a week becomes unusually busy, preserve the sequence: 2 focused coding sessions, 1 concept/revision session, and a short weekly review. Move unfinished work forward; do not pretend the topic is complete.
